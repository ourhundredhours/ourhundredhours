How I Built My Website With GitHub and Cloudflare Pages

📅 3 August 2026 ⏱ 12 min read

Building a website always felt like something that required advanced technical skills.

Before starting this journey, my understanding of websites was very limited. I only knew some basic HTML and CSS.

Concepts like hosting, servers, domains, DNS, and deployment were completely unfamiliar.

At that time, creating a website seemed like something that only developers could do.

However, I wanted to build something of my own.

I wanted a place where I could share my learning journey, document my projects, and create a digital space that belonged to me.

Instead of waiting until I understood everything, I decided to learn by building.

That became the beginning of my website journey.

Why I Wanted To Build My Own Website

Many people start their online presence through existing platforms.

Social media platforms are convenient, but there is always a limitation.

The platform controls the design, user experience, and how content reaches people.

A personal website provides something different.

It becomes a place that you own.

A place where you can:

Share knowledge

Document projects

Build your personal brand

Create long-term value

The goal was not to create a perfect website immediately.

The goal was to create a foundation and improve it step by step.

Learning How Websites Actually Work

Before building the website, there were many things that needed to be understood.

A website is not just a visual page.

Behind every website, there are several important parts:

Domain Name

The address people use to visit a website.

For example:

yourwebsite.com

Hosting

The place where website files are stored so people can access them online.

Website Files

The actual files that create the website.

For a simple static website, these usually include:

HTML

CSS

JavaScript

Images

Previously, website hosting seemed complicated and expensive.

Then I discovered another approach:

GitHub + Cloudflare Pages.

This changed the way I looked at website building.

Why I Chose GitHub and Cloudflare Pages

There are many ways to create a website.

Some people use website builders.

Some use content management systems.

Some use traditional web hosting.

For this project, GitHub and Cloudflare Pages felt like the right choice.

GitHub allows website files to be stored and managed.

Although many people know GitHub as a platform for developers, it can also be used for managing a static website project.

Cloudflare Pages connects with GitHub and automatically publishes website files online.

The workflow became simple:

Create website files → Upload to GitHub → Connect Cloudflare Pages → Website goes live

This approach removed the need to manage a traditional hosting server.

It allowed more time to focus on learning, creating, and improving the website.

Step-by-Step: How I Built My Website

After understanding the basic concept, the next challenge was turning the idea into a real website.

The process became much easier when broken into smaller steps.

The first step was creating a GitHub account and setting up a repository.

A repository is basically a folder where website files are stored and managed.

For a simple static website, the structure looks like this:

website/
├── index.html
├── style.css
├── script.js
└── images/

Each file has its own purpose.

index.html

This is the most important file.

It controls the main structure of the website and usually acts as the homepage.

style.css

This controls the visual appearance:

Layout

Colors

Spacing

Typography

script.js

This adds interactive features and allows the website to respond to user actions.

images/

This stores visual content used throughout the website.

At this stage, the focus was not creating something complicated.

The goal was simply creating a foundation that could grow over time.

After creating the repository, the next step was uploading the website files.

A simple website may look basic, but each element plays an important role.

HTML creates the structure.

CSS creates the design.

JavaScript adds interaction.

Images create visual experiences.

When these elements work together, even a simple website can become something meaningful.

The important lesson was that advanced technology is not always required to start.

Understanding the basics and putting them together is already enough to create something real.

The next step was connecting the GitHub repository with Cloudflare Pages.

Cloudflare Pages automatically detects the website files stored in GitHub and deploys them online.

After completing the setup process, the website became available through a public URL.

Seeing the website live for the first time was a meaningful moment.

A project that started with a few simple files had become a real website that people could access from anywhere.

That experience changed my understanding of building online projects.

The final step was connecting a personal domain.

This required learning about DNS settings and domain configuration.

At first, terms like:

DNS records

Nameservers

Domain settings

felt technical.

But after going through the process, these concepts became much easier to understand.

Once everything was configured correctly, the website became accessible through my own domain.

No traditional hosting plan was required.

The entire setup was built using GitHub and Cloudflare Pages.

The Challenges I Faced

The process was not always smooth.

There were many new concepts to learn.

Understanding GitHub

At the beginning, GitHub felt confusing.

Terms like:

Repository

Commit

Branch

Deployment

were completely new.

Instead of trying to understand everything at once, the focus was only on learning what was needed.

The goal was simple:

Learn enough to upload files.

Learn enough to update the website.

Then continue improving.

Understanding Website Deployment

Publishing a website for the first time also created many questions.

Why does the website update automatically?

Why does a small change require deployment?

Why does the website sometimes need time before changes appear?

These were things that only became clear through practice.

Reading about concepts helped, but experiencing the process created a deeper understanding.

Connecting The Domain

Connecting a personal domain was another challenge.

DNS settings were completely unfamiliar.

There were moments when the website did not work immediately.

Instead of seeing these problems as failures, they became opportunities to understand how websites actually work.

Every problem solved became another skill gained.

What I Learned From Building My First Website

The biggest lesson was simple:

You do not need to know everything before starting.

Before this project, website building felt like something that required professional knowledge.

But the process showed something different.

The fastest way to learn is often by creating something real.

When a problem appears, there is a reason to learn.

When there is something to build, knowledge becomes more meaningful.

Small progress creates confidence.

What Beginners Can Learn From My Experience

If you want to build your first website, start simple.

Learn The Fundamentals

Basic HTML and CSS are enough to create your first version.

You do not need to master every technology before beginning.

Build Before You Feel Ready

Many people wait until they have the perfect plan.

But the first version does not need to be perfect.

A simple website that exists can always be improved.

A perfect idea that never starts cannot grow.

Learn Step By Step

Technology can feel overwhelming because there are many things to learn.

The solution is not learning everything at once.

Learn based on the problems you face.

Each challenge becomes part of your learning journey.

Create Something You Own

A personal website is more than a webpage.

It is a place to collect knowledge, share experiences, and document growth.

Over time, it becomes a reflection of your journey.

Continuing The Journey

Building this website was not only about creating an online page.

It was about proving that learning through action works.

The journey started with basic HTML and CSS.

Then it expanded into GitHub, Cloudflare Pages, domains, and website deployment.

There are still many things to improve.

But every update, mistake, and improvement moves the project forward.

Progress does not come from waiting until everything is perfect.

It comes from taking the first step.

Learn.

Build.

Reflect.

Improve.

Every step counts.
